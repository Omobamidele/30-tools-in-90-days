# 4. PRODUCT DESIGN PHILOSOPHY

The interface must prioritize:

### CLARITY

Users should immediately understand:

* where they are
* what they are looking at
* what requires attention
* what they can do
* what happens next

### INFORMATION DENSITY

Business software should efficiently communicate meaningful information.

Do not waste the interface on decorative elements.

### CONTEXT

When users open a record, they should have enough context to make a decision without constantly jumping between screens.

### ACTIONABILITY

Every major screen should help the user do something.

### CONSISTENCY

Components, spacing, typography, tables, buttons, forms, filters and interactions must behave consistently.

### PROGRESSIVE DISCLOSURE

Do not overwhelm users with every option immediately.

Show what matters first and expose advanced functionality when needed.

# WORKSPACE RULES

These rules govern the folder structure of this workspace.

1. **One folder per tool.** Tool NN lives in `tool-NN/`. When an industry is assigned, rename it to `tool-NN-<industry-slug>` (e.g. `tool-01-freight-brokerage`) before any code exists, and update [README.md](README.md) and [PORTS.md](PORTS.md).
2. **Fixed ports — every tool has its own localhost.** See [PORTS.md](PORTS.md).
   - App / frontend: `30NN` (Tool 01 → `3001`, Tool 30 → `3030`)
   - Separate API / worker (only if needed): `40NN`
   - Local database / other service (only if needed): `54NN`
   - Never use port `3000`. Pin the port in the dev script itself with strict-port behaviour (e.g. `next dev -p 3007`, `vite --port 3007 --strictPort`) so a tool never silently drifts to another port.
3. **Fully independent projects.** Each tool has its own dependencies, `.env`, database and git repository (initialised when the build starts). No shared code between tools; if a pattern is worth reusing, copy it deliberately and document it.
4. **Phase gates are mandatory.** Research → Opportunity Discovery (user selects) → Spec → UX → Architecture → Build. Each phase's output is written to the tool's `docs/` folder.
5. **Keep the tracker current.** Update the status table in [README.md](README.md) whenever a tool changes phase.
